# ADR-0006 - Orquestrador é dono da quota; fonte externa declara não-quotada

- Status: aceita
- Data: 2026-08-30
- Escopo: datareview_v4 (apps/api)

## Contexto

O v4 expõe coleta via `POST /api/run`. Fontes portadas podem usar a própria API
oficial (Wikipedia, GitHub, HN…) sem custo de cota, mas o fallback SerpAPI tem
cota mensal escassa (plano Free: 250 buscas/mês — ver ADR-0002). Se cada fonte
controlasse a própria cota de forma descentralizada, o fallback poderia ser
acionado duas vezes na mesma coleta e estourar a cota fora de controle.

## Decisão

- **O orquestrador `runSourceWithFallback` é o único dono da quota**: decide
  quando bater na fonte primária, quando cair no fallback e quando persistir,
  contabilizando cada chamada paga em um único lugar.
- Fontes que já consomem cota externamente (ex.: SerpAPI com `SERPAPI_KEY` no
  plano Free) declaram `quotaManagedExternally: true`. Nesses casos o mesmo
  objeto `quota` é injetado nos dois níveis (fonte e orquestrador) para que a
  leitura seja coerente e o decremento aconteça exatamente uma vez.
- O fallback só é acionado em falha real da primária (erro estruturado,
  rate-limit/bloqueio 429/403, rede), nunca como caminho padrão nem pré-fetch
  (reforço da ADR-0002). Quando usado, o item marca `fallback.engine`.

## Consequências

Positivas: fluxo de cota previsível; testes herméticos das rotas não gastam cota
(adaptador falso). Riscos: responsabilidade concentrada no orquestrador exige
que o fallback read use o mesmo objeto de quota (verificado por teste).

## Referências

- `apps/api/src/routes.ts` (rota POST /run → `runSourceWithFallback`)
- `apps/api/src/deps.ts` (`SerpApiSource` com `quotaManagedExternally: true`)
