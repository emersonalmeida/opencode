# ADR-0005 - Núcleo hexagonal da v3 + front enxuto com design da v1

- Status: aceita
- Data: 2026-08-30
- Escopo: datareview_v4

## Contexto

O repositório tem três gerações: v1 (monólito Next com ~63 rotas, design system
shadcn próprio e coletores frágeis por scraping/endpoint não oficial), v2 (front
isolado + API monolítica) e v3 (núcleo hexagonal `contracts`/`domain`/`sources`
em TS puro, com catálogo declarativo, sem runtime próprio). O v4 precisa juntar
o melhor de cada um sem herdar o excesso: front pequeno e rápido + coleta
resiliente com validação por testes.

## Decisão

- **Núcleo do v4** = pacotes da v3 (`packages/contracts`, `packages/domain`,
  `packages/sources`) reaproveitados como fonte de verdade (catálogo, auditoria,
  normalização). Nada de duplicar modelos.
- **Runtime**: novo workspace pnpm com dois apps: `apps/api` (Express fino +
  storage SQLite `node:sqlite`) e `apps/web` (Vite + React + react-router,
  SPA servida pelo próprio Vite com proxy `/api` → API local).
- **Front enxuto**: apenas as rotas que valem a pena do legado — Home, Fontes
  (teste de qualquer fonte), Auditoria e Dataset. Nada das ~60 páginas
  administrativas de análise manual que o v1 acumulou.
- **Design**: tokens CSS HSL espelhando o design system do v1 (dark default),
  sem Tailwind/shadcn — CSS puro em `tokens.css` + `global.css`.

## Consequências

Positivas: núcleo testado (55 testes) reutilizado; front pequeno que carrega
rápido e é fácil de manter; jornada de validação (testar fonte → ver resultado →
auditoria → dataset) direto na UI. Riscos: fontes sem coletor no núcleo têm de
ser portadas (ponte v1→v4) ou ficam catalogadas como `bridge`.
