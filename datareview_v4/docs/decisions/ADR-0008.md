# ADR-0008 - Erro honesto (partial-OK) e persistência Bronze/Silver por run

- Status: aceita
- Data: 2026-08-30
- Escopo: datareview_v4

## Contexto

Fontes públicas falham por natureza (rate-limit, bloqueio de datacenter, rede).
Um run pode retornar itens E, ao mesmo tempo, reportar erro da fonte — os v1/v2
tratavam isso como "falha" binária e perdiam o dado parcial. Também não havia
revisão entre "dado bruto da fonte" (Bronze) e "contexto capturado" (Silver) na
mesma coleção.

## Decisão

- **Run devolve resposta estruturada**: `{ source, added, total, response: { items,
  error?, cached? } }`. Erro real da fonte NÃO derruba o run — vira
  `response.error` honesto com o que veio (parcial-OK). Fonte desconhecida →
  404; fonte conhecida sem coletor → 501 com o manifest do catálogo (status
  `bridge`/`planned`).
- **Persistência**: `sqlite` (`node:sqlite`) em `apps/api/.data/dataset.sqlite`
  (gitignored). Itens viram linhas prefixed `key = source#id`, com payload
  completo e `collectedAt`. O mesmo run sobreposto usa o key para não duplicar.
- **Cache curto** (fase de testes) evita bater na fonte a cada reload da página;
  em cache não re-persiste (dataset guarda coleções de runs frescos).
- **Leitura**: `/dataset` (linhas), `/stats` (total, por fonte, por tipo, com
  score, newest) e `/derive` (mesmo stats + hint determinístico p/ contexto de
  IA) alimentam a página Dataset e a Home.

## Consequências

Positivas: dado nunca se perde por erro parcial; comportamento de cada fonte é
auditável e honesto na UI (badge de erro na página Fontes). Riscos: storage
nativo simples não tem multiusuário nem migrations — reavaliar com o uso.
