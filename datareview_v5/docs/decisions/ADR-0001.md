# ADR-0001 - Núcleo de fontes com ativação por padrão e prioridade sem-auth

- Status: aceita
- Data: 2026-08-30
- Escopo: datareview_v5

## Contexto

A v4 tem 59 fontes catalogadas, todas com coletor (deploy atual: 59/59
implemented), espalhadas entre catálogo,, adaptadores no app API e página de
teste. O usuário quer uma evolução v5 que:

- tenha **todas as fontes** atuais,
- deixe **ativas por padrão** um subconjunto prioritário — `suggest`, `trends`,
  `serp`, `youtube`, `googleplay`, `apple`, `producthunt` e `reclameaqui` — com
  opção de ativar o restante na UI,
- priorize **fontes que não precisam de autenticação**,
- seja um **núcleo de fontes** organizado, com boas práticas de arquitetura e
  menos complicação,
- **extraia o máximo de dados de cada fonte** (fonte-a-fonte: dados,
  metadados, parâmetros, recursos, possibilidades).

## Decisão

- **Ativação é estado derivável**, nunca duplicado por fonte: o catálogo declara
  `enabledByDefault` (8 fontes) e a UI aplica overrides locais de usuário em cima.

- **Prioridade sem-auth** é uma função pura do catálogo (`authPriority`:
  `none` > `byok` > `oauth`), usada para ordenar/store os defaults e filtrar
  a UI (badges "sem chave", seção "prioridade: públicas primeiro").
- **Máximo de dados**: todo payload bruto da fonte é preservado em `meta`
  (Bronze, auditável) e o catálogo documenta campos devolvidos (`data`),
  parâmetros (`params`), recurso (`resource`), chaves (`keys`), capacidades e
  possibilidades de engine/ação — a página v5 exibe isso fonte-a-fonte.

## Consequências

Positivas: núcleo organizado e testável; fonte nova = 1 linha no catálogo +
  adaptador; ativação local na UI sem backend; prioridade sem-auth guia
  defaults na direção certa (públicas primeiro,. Riscos: usuário pode ativar
  fontes com chave BYOK sem configurá-lasˆ— mitigado com badges claros de `auth`.
