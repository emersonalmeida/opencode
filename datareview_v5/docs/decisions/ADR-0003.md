# ADR-0003 - Adaptadores vivem no núcleo `packages/sources` (não em apps)

- Status: aceita
- Data: 2026-08-30
- Escopo: datareview_v5

## Contexto

Na v4, os adaptadores de fonte moram em `apps/api/src/adapters/` —
acoplados ao app Express, com helpers de HTTP e catálogo em pacotes
separados. O objetivo da v5 é um **núcleo de fontes** organizado e com
menos complicação: toda a lógica de coleta deve ser reutilizável por qualquer
consumidor (app web, CLI, testes), sem depender de um servidor HTTP.

## Decisão

- **Todos os adaptadores vivem em `packages/sources/src/adapters/`**, importando
  só `@v5/contracts` e `@v5/domain` (zero deps de runtime externas).
- O registry `src/adapters/registry.ts` mapeia id-do-catálogo → factory limpa
  (sem chaves de ambiente: chaves BYOK entram via argumento `keys`).
- O app web da v5 consome o catálogo/ativação diretamente do núcleo
  (SSR/hidratação)) e, para coleta real,vai a uma API fina que só faz
  `runSource(adapter, options)` — nunca abriga adaptadores.



## Consequências

Positivas: núcleo completo (catalog + ativação + adaptadores) testável sem
rede/servidor; a mesma fonte serve web,CLI e testes; menos camadas.
Riscos:
escrever adaptadores no pacote exige cuidar de não puxar deps do
`apps/api` da v4 — resolvido portando só o necessário (helpers em `shared.ts`).
