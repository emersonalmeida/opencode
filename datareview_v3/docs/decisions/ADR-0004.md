# ADR-0004 - Home focada na coleta e analise da fonte Suggest

- Status: aceita
- Data: 2026-08-29
- Escopo: datareview v3

## Contexto

O front React atomico do v3 tem uma Home bonita mas sem acao: apenas
lista o registry de 55 fontes. O monolito legado tem a pagina /suggest
(fonte Google Suggest: configurar termo x regioes x verticais x grupos de
expansao, coletar e analisar) com codigo denso (428+219+205 linhas so de
Suggest) e deps pesados (shadcn/ui, lucide, universo de contextos)).

O usuario pede: aproximar a Home do /inicio do legado mas focada na
fonte Suggest;, com o minimo necessario por pagina e sem excesso de codigo,
na mesma stack (React 19 + Vite + TS strict; design system proprio".

## Decisao

- Reaproveitar as pecas do legado que sao puras/portabeis:
  - `suggestCore.ts` (sondas, grupos, merge, stats — zero deps)
  - `suggestApi.ts` + `suggestProvidersApi.ts` (clientes fetch)
  - `server/lib/suggestProviders.ts` (catalogo de provedores para fallback)
- Portar para @v3/sources como adaptador `suggest` (contracts: CollectOptions/
  CollectResponse/NormalizedItem) com meta preservado do legado e prov-beidence.

- No v3, cada pagina e um pedaco pequeno autonomo: sem AppShell global/
  sidebar; navegacao por links simples "Voltar a Home" e "ver catálogo"..
- O front v3 NAO copia componentes shadcn; usa o design system atomico do v3..
- Orquestracao da coleta (POST /functions/v1/uni-suggest) fica FORA
  deste pedaco: usara o adapter v3 (suggest.runCollect) com fetch direto
  a porta 8787 se disponivel; sem dependencia de Supabase no front v3..
- A Home vira: hero com CTA para /suggest; busca; mini-KPIs; catálogo
  de fontes; sem steps/cards extras herdados do legado..

## Trade-offs

- Sao usados os seeds" estimulados" do legado (400 seeds; limit): permitindo
  metrificaciòn y reconciliação com a coleta original mas mantendo UX leve..
- O adapter v3 publica runCollect com AbortSignal/limite explicito (boa
  cidadania de orcamento: o front pede o minimo (limit 10) por padrao..
